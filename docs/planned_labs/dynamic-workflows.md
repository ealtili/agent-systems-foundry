## Systems context
A dynamic workflow moves the orchestration plan out of the model's turn-by-turn judgment and into a script: the script owns the loop, branching, and intermediate results. This lab measures what that buys (main-context tokens, repeatability, resumability, cross-checking) against what it costs (agent count, latency, no mid-run user input) on two runtimes, in Python.

## What each runtime gives you (verified against installed packages)
- **Antigravity SDK (Python, beta):** `Agent.run_workflow(workflow=<@workflows.define fn>, script_path=..., args=...)`. Scripts are Python using `phase`, `log`, `agent`, `call_tool`, `parallel`, `pipeline`, `args`; they are AST-validated; spawned agents can run in `inherit`, `branch` or `share` (git worktree) workspaces. Needs `enable_subagents=True` and `BuiltinTools.RUN_WORKFLOW` enabled.
- **Claude Code (driven from Python):** workflows are JavaScript scripts that Claude writes or you save under `.claude/workflows/`. The Python Agent SDK has **no authoring API**; it drives the bundled Claude Code CLI with a prompt, requires a `Workflow` allow rule (or hook / `can_use_tool` / auto / bypass mode) because there is no interactive prompt, and reports workflow tasks. The `ultracode` keyword only counts when the prompt is stamped `origin: {"kind": "human"}`.

## Task spec (learner-owned core)
1. Write the Antigravity workflow by hand in Python: fan out per file, then an adversarial verification phase with a different prompt; structured results; handle failed agents without losing the batch.
2. Write the Python driver for the Claude Code workflow: allowed tools, deadline, permission mode, and a parser for workflow task messages. Let Claude author the JS script, then read it and explain every primitive; save it as `/<name>`.
3. Slice first: run each on one directory, record agent count and tokens before any larger run. Live runs exceed the 20k-token threshold: ask for approval with a dollar estimate.
4. Prove resume semantics on Claude's side: edit one prompt, relaunch, and predict beforehand which agents rerun.
5. Policy on Antigravity: deny by default, allow reads, ask for writes; show a `ToolError` from a denied call.
6. Write the comparison table: determinism, flexibility, debuggability, cost, safety, reproducibility.
